# 画面选择规则与参考案例

用于剪后口播的画面策划：目标是降低理解和寻找信息的负担，必要时建立证据、突出重点。先决定需要被看到的关系，再寻找实现。卡片是一种容器，是否有用取决于它表达的信息与变化。

## 来源与使用边界

提炼自用户提供的三份报告，保留文件名便于追溯；本文件保存规则与关键案例，不依赖 Downloads 路径，其他机器使用本仓库也可读取：

- `视频1_vs_视频2_逐帧拆解报告.md`：第八章语义关系、第九章节奏、第十三章检查建议，以及第六章人物构图。
- `01_两条视频_逐帧扫描与视觉事件时间轴.md`：视频1各段的视觉信息作用、视频2的复述与通用素材问题、整片强弱切换。
- `02_优秀包装参考与通用规则.md`：优秀案例的迁移条件、不适用条件及五步选择方法。

下述时间和画面描述来自报告，本次没有重新扫描源视频验证。它们是用户提供的参考观察，不是所有视频都应满足的实验指标。提取解释方法，不固定效果、颜色、构图或切换频率；也不照搬报告中的文案改写建议。

## 先确定画面带来的收益

对每个意义段，具体回答：

- **难点**：观众只听口播时，可能把什么混淆、遗漏或找不到？
- **画面补充**：哪种位置、连接、变化或真实细节能减少这项困难？
- **取舍**：这种表达是否比短强调或保留人物更值得观众分配注意力？

没有必须可视化的关系，不意味着需要另找素材填满。开场建立讲述者、自然衔接、情绪表达、前一强段后的消化，都可能适合干净人物画面。主题首次出现也可以只做短标识，不能把所有工具介绍强制扩成完整流程。

工作台使用现有 `viewer_goal`、`reason`、`initial_state`、`actions`、`final_state`、`materials` 字段；无须新增形式化评分。`reason` 必须与这一段的具体对象和难点有关。

## 关系决定表达，关键词仅是线索

| 口播实际表达 | 优先思考的画面 | 避免的误用 |
|---|---|---|
| 真正平级的类别或总结 | 同层并列，逐项聚焦，必要时计数 | 一看到“三个”就做三张卡，不检查关系 |
| 先后执行 | 固定路线、操作接力，展示当前与已完成状态 | 把步骤画成互不相干的平级标签 |
| 原因导致结果 | 同一主体因条件改变而产生可见结果 | 没有因果依据也画箭头；把先后当因果 |
| 对比、反转、不等于 | 可比较的对象与维度，反转处改变关系 | 只把两个观点再打一遍大字 |
| 输入经过处理成为输出 | 保留输入、处理与结果的连续位置关系 | 用软件 Logo 或剪辑台 B-roll 代替能力解释 |
| 一次建立、多次复用 | 一个母体保持，换内容或参数，派生多个结果 | 普通三条清单，丢掉共享母体 |
| 核心与多个关联因素 | 核心固定，周边节点按关系连接 | 所有类别都画中心网络，不管实际逻辑 |
| 多任务并行 | 同一系统内多个任务同处活跃状态 | 画成一个做完才做下一个的流程 |
| 演进、升级或进入更深层系统 | 路径、层级或主体状态逐步升级 | 各阶段同层罗列，只有标题不同 |
| 条件决定选择 | 以需求或条件为入口的分支或选择矩阵 | 只列工具名；为看起来复杂制造条件 |
| 规模、汇聚、多来源 | 多个来源汇入、数量增长或高密内容群 | 用卡墙表达普通三点，把热闹当信息 |
| 数量、程度或变化 | 有依据的数值、长度、趋势或定性状态 | 没有数值来源也使用精确百分比或仪表盘 |
| 实际操作或证据 | 真实界面局部、关键细节与定位关系 | 整页缩得不可读；用官网首页证明工具效果 |

以上是候选思路，不是强制结构清单。特殊关系说明具体对象及连接，沿用 `custom` 等现有合同；后续模板不能反向修改它。

## 参考案例如何迁移

案例时间来自报告的视频1；问题对照来自报告的视频2。参考编号仅用于内部策划理由。

| 编号与参考 | 借鉴的方法 | 使用条件与限制 |
|---|---|---|
| R01 · 9–13s 团队结构 | 核心与各岗位连接，让协作关系可见 | 确有核心与协作关系；不能仅因有五个名词就画网络 |
| R02 · 17–21s 原型→测试→修改 | 主体或焦点沿流程推进 | 口播确有顺序；每个动作锚定对应剪后短语 |
| R03 · 25–31s 页面到业务系统 | 同一页面展开为更深层系统，表达层级升级 | 说明具体多了什么关系；不能只换字号和背景 |
| R04 · 43–47s 杠杆演进 | 向上路径呈现阶段发展 | 存在演进逻辑；不暗示未经证明的增长数值 |
| R05 · 49–53s AI 任务面板 | 把多个能力放在同一工具系统内 | 解释性面板标示意；实际产品能力演示需真实证据 |
| R06 · 63–69s 多窗口 | 多个任务同时在场，呈现并行与反馈 | 确实并行；分层聚焦，控制阅读负担 |
| R07 · 97–104s 内容汇聚 | 多来源聚成矩阵，表现规模 | 规模确为重点时用，普通三点不用高密墙 |
| R08 · 117–124s 三种资产 | 真正平级的分类可用计数与列表 | 保留分类含义；不能拿来替代流程或一变多 |
| R09 · 129–135s 人的价值居中 | 把句子中的“中心”表现为空间中心 | 只借鉴关系，字体与配色服从当前项目 |
| R10 · 视频2 39–51s 复用被做成列表 | 改为母模板→换内容→多个产物 | 表达共享母体与重复收益，不默认展示官网 |
| R11 · 视频2 67–81s 剪辑功能被素材代替 | 用时间线状态解释删除、字幕与画面轨 | 示意不冒充 ChatCut 实操；真实演示需读回当前界面素材 |
| R12 · 视频2 99–108s 工具选择总结 | 需求入口连接对应工具与结果 | 选择依据来自口播；不添加未经验证的性能排名 |

理由示例：

“难点：三项功能听起来像互不相关的步骤，观众看不出同一时间线如何被修改；画面补充：保留一条时间线，先删掉冗余片段并合拢，再增加字幕轨和画面轨，顺着对应口播逐步改变。借鉴 R11 的状态变化方法，使用解释性示意。”

“难点：观众容易把安装成功当成已经满足需求；画面补充：安装标记先亮，任务结果仍待核验，说到实际跑一次时才转向结果位。一个小对比足够，无需新增复杂界面。”

这类理由有具体对象与信息收益；“为了丰富画面，用结构帮助理解”无法解释选择，不应直接进入制作。

## 动作、阅读与整片节奏

开始画面交代对象；随口播增加关系、改变状态或转移观察焦点；结束画面保留可理解的结果。需要阅读的真实文字留出停留，动作不压过重要口播。高密信息逐步建立，保持一个主阅读焦点，不把大量内容同时扔给观众。

报告中的“重要段每2–4秒变化”“连续人物5秒检查”“同构图6秒检查”“静态截图2–3秒”“15–25秒重置”只作策划审阅线索：

- 有新的可视化含义却长期不变化，检查是否遗漏表达。
- 人物正在承担情绪、解释或呼吸任务，可以继续停留。
- 截图需要阅读或操作定位，可以保留更久。
- 连续高强度后，检查是否需要回人物；不能为达到时间阈值加无关动画。

不据此更改现有 Gate B 的程序阈值、不硬规定每几秒切镜头。新标题、颜色和模板替换不自动算新的信息状态。整片回看结构、主焦点、强弱与重复，模板不同但构图相同仍可能重复。

## 人物、素材与实现交接

依据当前实拍帧确认脸部、字幕区和实际留白；参考中景不意味着当前近景也能放同样大小的关系图。留白不足时调整取景、人物模式或简化表达，不能先挡脸再靠动效补救。

真实界面承担操作定位或证据；解释性结构承担关系说明，二者可以组合。泛化 B-roll 要写明观众能从中获得的具体信息。截图在动画之前完成网页链接、仓库地址和具体 Skill 名称的像素遮盖；人物模式及保护区交 Shotbook 落实。

画面策划不决定卡片、字号坐标、SFX 与配乐实现。先在工作台确认信息作用与文字分镜，后续层再按项目风格和语义轻重实现。检查字段与时间通过，只说明合同一致；观感仍需稳定帧和实际播放验证。
