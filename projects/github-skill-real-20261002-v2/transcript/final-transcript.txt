以后你缺什么工具，

直接让 AI 去 GitHub 上面帮你找。
比如你想找 Codex、
Skill、 PPT 工具。
视频处理工具，
甚至一个非常具体的一个小功能，
都可以用这个方法。
先跟大家讲一下 GitHub 是什么？
你可以把它理解成一个巨大的项目仓库。
很多开发者会把自己做的 AI 工具、
开源项目、
学习资料
还有各种 Skill 都放到里面。
但是其实普通人不用学 GitHub 这么复杂。
你只需要会三件事情，
会搜，会看。
会复制链接。
先打开 GitHub
没有账号的话点击右上角的 Sign up
按照提示注册一个免费账号就可以了。
接下来我们直接看顶部这个搜索框。
比如我要找 Codex 能用的 Skill 可以先搜 Codex Skills。
想找 PPT 相关的，
就搜 PPT Skill。
搜索之后记得点击 Repositories。
Repositories 就是项目仓库。
这里再教你一个非常好用的小技巧。
如果你不是想找某一个工具。
而是想一次性找一批同类型的项目，
可以在关键词面前加。
Awesome
比如 ███████。
你经常会看到这种项目，
里面已经帮你整理好了几十个甚至上百个同类型的工具。
看到感兴趣的你再点进去。
然后看搜索旁边结果这个 star
你可以简单的把它理解成项目在 GitHub 上有多少人关注和收藏。
可以先按照
Most stars 排序，
看看关注度比较高的项目。
但值得注意，
Star 多只代表关注的人多，
不代表它一定适合你。
所以真正重要的是点进去看它的。
README。
README 就是这个项目的说明书。
英文不用全部看懂，
你先找三个东西。
它是干什么的？
效果是什么样的？
然后怎么安装和使用？
看不懂的我们直接让浏览器翻译，
然后或者把项目链接直接丢给 AI 让它告诉你这个项目是干什么的。
确定这个项目可能有用之后，
我们复制浏览器的地址，
你的 GitHub 的链接，
然后直接发给 Codex
我们只需要告诉 Codex 帮我检查一下这个项目能不能够在 Codex 里面进行使用。
需要安装什么，
有没有额外的费用，
如果可以，
帮我安装好。
用一个简单的例子告诉我怎样去使用。
到这里其实还没有结束，
安装成功不代表这个工具真的就有用，
一定要让 Codex 再实际跑一次。
比如这是一个 PPT Skill 你就把一段内容丢给它。
让它生成一份真正的 PPT。
这是一个视频工具，
你就真正让它处理一次视频。
跑出来了之后，
而且结果符合了要求，
这才是你需要的一个工具。
所以以后你再找 AI 工具，
记住这个流程。
先搜需求，
找到项目，
然后看它的项目介绍，
然后复制链接，
把它发送给你的 AI。
去检查、安装和测试。
学会了这个之后，
你就不用天天等别人告诉你，
最近又出了一个新的 Skill 你完全可以自己去找。
